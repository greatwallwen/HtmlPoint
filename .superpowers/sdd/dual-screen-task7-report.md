# Dual-screen Task 7 report

- State: the existing authenticated `/v1/jobs` endpoint now accepts exactly six projection job discriminators and dispatches them directly to the Helper-owned native supervisor. This phase does not simulate hardware, assign a physical screen, or make a dual-screen certification claim.
- Schema boundary: every job contains only a UUID command identity, the exact nullable/required session identity, a strict bounded generation, and one command-specific payload. Detect/fullscreen/verify/close payloads are empty, assign accepts only strict boolean `swap`, and open accepts only published course, slide-deck, and runtime-manifest identities. Extra URL, path, HWND, token, shell, manifest, course, and asset-byte fields fail before dispatch.
- Execution boundary: projection jobs never enter `BoundedJobRunner` or a worker subprocess. The App session guard remains mandatory, and each discriminator maps to exactly one corresponding `ProjectionHostSupervisor` method while preserving `commandId`, `sessionId`, and `expectedGeneration` unchanged.
- Concurrency boundary: an app-scoped gate admits one projection command at a time before the supervisor. Timeout or request cancellation invokes `cancel_current` off the event loop and waits for an independent shielded cleanup task to observe the command thread's exit before returning or releasing the gate. Repeated task cancellation cannot reopen a late-side-effect window.
- Response boundary: the browser receives a typed path-free projection receipt and runtime evidence. Native receipt messages are reduced to a small public rejection allowlist or generic accepted/rejected text. Missing supervision, timeout, replay collision, content failure, and unexpected exceptions map to bounded status/reason codes without raw exception, path, secret, command payload, or process detail.
- TDD and review learning: initial tests failed because the six schemas were absent. A first read-only review found that `asyncio.to_thread` timeout did not stop the worker and global cancellation could affect another queued command; a second pass found repeated `Task.cancel()` could interrupt cleanup. Both were closed with the pre-supervisor gate and independent cancellation cleanup task. The final review found no Critical or Important issue.
- Verification: strict projection/API/publication tests passed 125 tests. The final complete offline Helper gate passed 899 tests with 8 existing environment/integration skips and 7 marker deselections; only existing third-party deprecation/duplicate-archive-fixture warnings remained. `git diff --check` and Black check for the new test file passed.
- Artifact lifecycle: source/tests, frozen inputs, phase requests/receipts, this reflection, `.tools`, model runtimes, databases, evidence, and `node_modules` are retained. Five Helper pytest/bytecode caches were removed (47 files, 1,674,016 bytes). The pre-existing root `.pytest_cache` remains retained under its inaccessible ACL and was not created by this phase. Git objects were compacted to one 3,837 KiB pack with zero loose or garbage objects.
