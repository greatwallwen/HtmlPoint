# 个人优先课程工作台设计

日期：2026-07-21
状态：已批准方向 A，待书面规格复核
决策人：用户
事实审计：`platform/web/evidence/product-audit-2026-07-20/audit.md`

## 1. 决策

课程平台采用单一的“个人自动组课”主线。个人用户选择本地资料或目录、填写一句课程需求后，平台在本地自动完成解析、知识卡组织、课程组合、图形编排、验证和发布准备，只在确有风险时集中展示一个注意事项包。

现有结构化内容、知识卡、检索、证据、Slide AST、运行清单和双屏状态机继续作为平台底层资产；现有四步专家治理流程不再作为默认产品入口。内部版本 ID、摘要值、任务 ID 和发布绑定只保留在合同与证据中，默认界面不展示。

实体双屏认证保持为独立的授课能力验收。它不被宣布完成，也不再阻塞个人创建和使用课程。

## 2. 问题与纠偏依据

实测当前产品有四个方向问题：

1. 直接打开 Web 时本地 Helper 未连接，但浏览器端仍能生成不可发布的固定模板课程，形成假成功。
2. 真实受控路径要求个人逐项处理大量知识卡审核、图形绑定、检索、验证和发布步骤。
3. 双屏授课与组课并列在主导航中，使尚未完成的实体认证在认知上阻塞组课价值。
4. 技术治理对象直接泄漏为用户任务，个人需要理解平台内部实现才能完成课程。

纠偏不是移除治理，而是把治理下沉到可恢复的本地编排器，将真正需要人工判断的少数问题上浮。

## 3. 用户与成功标准

首要用户是使用 Win11 的个人讲师、培训师或内容创作者。他们拥有若干 Markdown、PPTX、PDF、Word、表格或数据集，希望快速形成一门可讲、可编辑、可追溯的课程。

首个产品闭环必须满足：

- 用户通过一个桌面入口启动平台，不需要分别启动 Node、Vite 和 Helper。
- 用户可以选择一个或多个文件，也可以选择目录。
- 课程名称为空时由可靠的来源标题和需求自动命名，而不是使用固定示例标题。
- 点击一次“开始组课”后，平台自动运行全部低风险步骤。
- 正常资料最多需要处理一个注意事项包；没有风险时直接进入课程预览。
- 生成结果来自已导入资料、已发布知识卡和有来源的图形，不得以固定模板冒充真实结果。
- 课程创建成功后即可预览、编辑和单屏使用；双屏授课是可选后续动作。
- 刷新或重启后可以恢复运行和已生成课程。

## 4. 产品流程

### 4.1 启动

发布形态由一个 Windows 启动入口拉起本地 Helper。Helper 提供构建后的 Web 静态资源、生成一次性会话材料并打开浏览器。个人用户不依赖开发服务器，也不会在正常启动路径看到“本地知识服务未连接”。

开发模式仍可使用独立 Vite 服务，但它不是产品入口。直接打开未绑定 Helper 的 Web 页面时，只显示明确的恢复页和“从课程工作台启动”说明，不再提供浏览器端模拟生成。

个人数据默认保存在 `%LOCALAPPDATA%/CourseStudio` 下的数据库、来源存储、制品、证据和恢复状态中。工作区内只保留源码、固定测试夹具和版本化验收证据。

### 4.2 创建课程

默认首页只呈现一个主任务：

1. 选择资料或目录。
2. 输入一句需求，例如“为个人讲师制作 60 分钟的 AI 工作流实战课”。
3. 可选展开高级设置：受众、时长、使用范围、是否必须包含数据证据或真实图形。
4. 点击“开始组课”。

标题、受众和学习目标允许由来源与需求推断。系统必须在预览页显示可直接编辑的人类可读结果，但不得要求用户填写或理解内部标识。

### 4.3 自动编排

界面显示人类可理解的阶段：读取资料、整理知识、编排课程、匹配图形、检查课程。每个阶段绑定真实运行状态和证据，不使用虚假进度。

完成后有两种结果：

- `ready`：直接进入课程预览。
- `needs_attention`：显示一个汇总注意事项包，用户可以接受推荐处理并继续，也可以展开单项修改。

不会把每张知识卡、每个版本或每次索引任务拆成连续审核页面。

### 4.4 课程使用

课程预览是主要完成页，提供：

- 查看和编辑章节、课节、讲稿与来源关系。
- 查看真实图形及其来源说明。
- 运行课程检查。
- 单屏预览或开始授课。
- 在具备条件时进入双屏授课。
- 通过“运行证据”抽屉查看内部收据；该入口默认收起。

双屏入口显示真实能力状态。未完成实体认证时可以明确进入排练，但不得显示“已认证”。

## 5. 领域模型与合同

新增四个稳定概念：

### 5.1 `PersonalCourseRequest`

包含人类需求文本、来源版本集合、可选标题、受众、目标时长、使用范围、图形要求和数据要求。所有字段有确定的 schema 版本、大小限制和规范化摘要。

### 5.2 `PersonalCourseRun`

持久化一次组课运行，至少包含：

- 不透明运行标识。
- 请求摘要和来源快照摘要。
- 当前状态与阶段。
- 已完成步骤及其证据引用。
- 注意事项包引用。
- 最终课程版本、Slide AST 和 RuntimeManifest 引用。
- 创建、更新时间与可恢复错误。

状态机为：

`queued -> importing -> organizing_knowledge -> composing -> assigning_visuals -> validating -> needs_attention | ready | failed`

从 `needs_attention` 接受或修改后回到产生问题的最小阶段。所有步骤必须幂等；相同请求和相同来源快照的重试不得创建重复发布对象。

### 5.3 `AttentionBundle`

只包含必须由人判断或会改变真实性的事项：

- 来源解析失败或关键内容缺失。
- 相互冲突或近似重复的知识卡。
- 关键结论没有来源覆盖。
- 图形许可、来源或真实性不明确。
- 数据集字段不足以支持请求的图表。

每项包含人类说明、推荐处理、影响范围和证据引用。默认动作必须安全、可逆，不得静默放宽真实性门槛。

### 5.4 `PersonalCourseResult`

返回人类标题、课程摘要、章节统计、来源覆盖、图形覆盖、注意事项计数、可用操作以及内部证据引用。浏览器默认投影过滤内部 ID 和摘要，只在证据抽屉按需展示。

## 6. 本地编排器

浏览器提交受类型约束的 `personal_course_create` 运行请求。Helper 中的 `PersonalCourseOrchestrator` 复用现有能力，按以下顺序执行：

1. 固定并验证来源快照。
2. 解析文件与目录，生成结构化 chunk、数据集描述和来源图形。
3. 自动命名候选知识单元，生成多标签知识卡。
4. 按个人安全策略自动接受、发布和索引低风险知识卡。
5. 检测冲突、重复、来源缺口与许可问题并汇总注意事项。
6. 召回已发布知识卡，组合可调整课程大纲。
7. 生成 Slide AST、讲稿和 RuntimeManifest。
8. 优先绑定 PPTX/文档中的真实图形；不足时检索带可靠来源和许可的网络真实图形。
9. 运行来源覆盖、时长、结构、图形真实性、运行清单和发布绑定检查。
10. 输出 `ready` 或单一 `AttentionBundle`。

浏览器不能执行任意 shell 命令。编排器只调用现有 allowlist runner 和新增的确定性领域服务。

## 7. 自动知识策略

低风险候选卡满足全部条件时自动发布和索引：

- 内容可以精确回溯到已固定来源 chunk。
- 没有开放的冲突或近似重复任务。
- 标签来自受控词表或确定性的来源分类规则。
- 没有未经允许的网络内容或许可不明图形。
- 版本更新保持来源与前一版本的 lineage。

知识卡支持多标签，并区分主题、技能、受众、难度、内容类型、数据领域和来源类型。新课程导入内容时优先升级已有知识单元；只有语义上独立的新内容才创建新单元。

系统生成的人类标题稳定、简短、无内部 ID。冲突、低置信度命名或重大语义变化进入注意事项包。

## 8. 图形真实性策略

图形选择优先级：

1. PPTX、文档或数据集中的原始图形。
2. 由固定数据集确定性生成的真实图表。
3. 具有落地页、作者或发布者、许可和抓取时间的网络真实图形。
4. 无可靠图形时保留明确缺口，不生成伪装为真实证据的装饰图。

所有可见图形绑定 `VisualAssetVersion` 和来源说明。网络检索失败、许可不明或原图变化不会静默降级为无来源占位图。

## 9. UI 结构

沿用现有亮色设计系统、字号、间距、Phosphor 图标和可访问控件，不重新发明视觉语言。默认产品只有三个顶层状态：

- `创建课程`：资料与一句需求。
- `正在组课`：真实阶段进度与可恢复状态。
- `我的课程`：预览、编辑、使用和可选授课。

现有知识审核、真实图形与发布面板中的专家细节迁入按需展开的“注意事项”和“运行证据”界面。核心操作仍使用有文本的按钮；图标按钮保持 `aria-label`、焦点、提示、约 44px 热区和 Escape 关闭行为。

## 10. 错误与恢复

- Helper 未启动：显示启动恢复页，不运行模拟课程生成。
- 单个来源失败：其余来源可以继续，失败项进入同一注意事项包。
- 进程重启：从最后一个已提交阶段恢复，不重复发布已完成对象。
- 网络图形不可用：继续使用来源图形或明确图形缺口；课程真实性状态可降级但不得伪造。
- 验证失败：停在 `needs_attention`，显示推荐修复，不进入已发布状态。
- 双屏不可用：课程仍可创建、编辑、预览和单屏使用。

## 11. 冗余清理边界

在相应替代路径通过测试后删除：

- `LocalCourseAgent` 固定模板生成及其离线假成功 UI、测试和样式。
- 默认流程中逐卡审核、逐图绑定和内部发布步骤的重复入口；领域服务与证据合同保留。
- 被新验收替代的旧视觉截图、失效的绝对工作树路径和只为旧默认流程服务的 QA 断言。
- 可复现的 `dist`、`.vite`、`bin`、`obj`、`__pycache__`、pytest、E2E 和 Playwright 输出。

不得删除：结构化 schema、迁移、来源 lineage、版本化验收收据、依赖、模型缓存、外部数据源或未被替代的双屏实现。

每个阶段结束写入清理收据，记录删除、保留、受 ACL 阻塞的目录和 Git 对象状态，然后运行 `git gc --prune=now`。没有新证据的重复扫描必须停止。

## 12. 测试与验收

实现必须按测试驱动完成，至少覆盖：

1. `PersonalCourseRequest`、运行状态机、注意事项包和结果投影的 schema 测试。
2. 编排器的幂等、恢复、部分来源失败、卡片升级、多标签和证据绑定测试。
3. Helper API 的会话认证、请求大小、重放和跨来源隔离测试。
4. 无 Helper 时明确拒绝模拟生成的 Web 测试。
5. 自动命名、单一注意事项包、隐藏内部 ID 和双屏不阻塞组课的组件测试。
6. 使用 Markdown、PPTX 与数据集夹具的一键真实浏览器流程。
7. Windows 产品启动烟雾测试：一个入口启动静态 Web 与 Helper 并恢复已有课程。
8. 当前设计系统下的桌面截图、键盘流、焦点恢复、控制台错误和失败请求检查。

里程碑验收命令：

- `python platform/qa/run.py all`
- `npm --prefix platform/web run typecheck`
- `npm --prefix platform/web run build`
- 新增的个人组课浏览器验收
- 与改动范围对应的 Helper 和 Windows 聚焦测试

完成标准不是“测试存在”，而是个人能够从一个真实启动入口导入资料，用一次主操作获得可预览、可追溯、可恢复的课程；默认界面不显示内部 ID，且未完成的实体双屏认证不影响该闭环。

## 13. 非目标

本阶段不包括：

- 宣称或伪造实体双屏认证。
- 云账户、多人协作、计费或托管搜索。
- 浏览器任意命令执行。
- 以生成式装饰图替代真实图形证据。
- 读取、复制或硬编码受保护目录内容。
- 一次性重写全部 Helper、知识库或双屏实现。

## 14. Supergrill 阶段关系

既有 `dual-screen-task9-real-pipeline-and-hardware` 阶段保持未完成，实体认证仍为 `false`。用户在 2026-07-21 明确选择方向 A，新的个人可用主线优先级高于实体认证，但这不是对旧阶段的虚假完成。

后续实施按可逆里程碑推进：产品启动与失败关闭 -> 个人组课合同和编排器 -> 简洁 UI -> 真实浏览器验收 -> 冗余源码与证据清理。每个里程碑都必须先验证、再清理、再反思。
