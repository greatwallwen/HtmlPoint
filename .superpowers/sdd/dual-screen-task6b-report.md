# Dual-screen Task 6B report

- State: the Helper now resolves one exact published course, slide deck, and runtime manifest into a bounded path-free Host bootstrap. This phase does not assign displays, open role windows, or make a physical dual-screen certification claim.
- Publication boundary: the open payload accepts only the three opaque publication identities. Every course, requirement, outline, deck, manifest, placement, visual placement, and artifact relationship is reopened from the catalog and verified against its immutable semantic digest.
- Snapshot boundary: the resolver freezes the catalog file and parent identities from opened handles. Each resolve holds non-replaceable leases on the parent, database, and existing WAL/SHM sidecars, establishes one SQLite read transaction, and verifies the same layout after the snapshot. Whole-file, parent, or sidecar replacement fails closed.
- Asset boundary: manifest artifact order is recomputed from the Slide AST. Every asset binding, including duplicate reuse across nodes, is checked against catalog metadata before each unique artifact is exposed once through `ArtifactStore.open_verified`.
- Host policy: projection is optional only when both the fixed policy and fixed executable are absent. Partial, malformed, duplicate-field, oversized, reparse, non-regular, or digest-mismatched installs fail before server launch. Policy bytes, size, type, and path identity are verified from the same locked descriptor; the Task 6A executable lease remains authoritative at Host launch.
- Lifecycle: `HelperRuntime` owns the optional projection supervisor. Browser-launch failure, server failure, normal return, interrupt, and shutdown failure all attempt a redacted bounded shutdown without exposing paths or secrets.
- TDD and failure learning: new tests first failed for the missing duplicate-binding helper and post-construction catalog replacement. A later WAL test exposed that the constructor's no-sidecar binding incorrectly rejected legitimate WAL catalogs; the constructor was corrected to bind existing sidecars as part of the same layout lease. The publication job fixture failure was clock drift in a fixed 2026-07-18 network receipt, not a product or reasoning defect, so the test now freezes the product clock rather than weakening expiry validation.
- Review: two read-only security passes found and closed catalog/sidecar TOCTOU, duplicate artifact binding overwrite, and policy stat/read replacement races. The final pass found no Critical or Important issue.
- Verification: after cleanup, cache-disabled focused and affected regression tests passed `105 passed, 2 skipped`; Black check and `git diff --check` passed. The skips are the existing explicitly gated real Host integration tests, not simulated certification.

Five Helper pytest/bytecode cache directories were removed (60 files, 2,291,535 bytes).
