# 个人可用性与产品方向审计

日期：2026-07-20
范围：当前主工作区中的课程平台 Web 主流程、Helper 连接方式、浏览器端离线回退与既有端到端验收。未读取或复制受保护目录。

## 实测路径

1. 直接打开当前 Web 工作台。
2. 导入 `browser-flow-fixture.md`。
3. 进入生成课程，填写个人受众与目标。
4. 在本地知识服务未连接时生成课程结构。
5. 对照现有真实 Helper 端到端测试中的审核、图形绑定、验证和发布步骤。

## 证据

- `01-import.png`：首页为四步专家流程；本地知识服务未连接时仍允许导入。
- `03-offline-generated.png`：离线回退生成了固定的“三章九节”通用课程，标题和章节没有真实反映导入的“个人 AI 工作流实战”资料。
- `e2e/knowledge-course.spec.ts`：真实受控路径需要逐项处理最多 30 个知识审核任务，再逐项绑定图形、生成图表、检索网络图形、验证并发布，才可进入授课。

## 结论

当前技术方向中的结构化内容、知识卡、证据、Slide AST、Helper 与双屏状态机是正确资产；产品主线发生了重大偏移：

- 个人组课被设计成专家治理流水线，首次成功成本过高。
- 直接打开 Web 时出现“服务未连接”，仍提供不可发布的模拟生成，形成假成功。
- 双屏授课与组课并列为主步骤，使尚未完成的实体双屏认证在认知上阻塞了个人价值闭环。
- 内部审核、发布和实体 ID 暴露过多，用户需要理解系统实现才能完成课程。

## 纠偏原则

1. 个人主线改为：选择资料或目录 -> 描述课程需求 -> 自动组课 -> 仅处理一个注意事项包 -> 预览/使用。
2. 所有真实工作仍由本地 Helper、结构化合同和证据对象完成；不再把浏览器端模板生成包装成可用课程。
3. 低风险知识卡自动命名、打多标签、发布和索引；冲突、缺来源、许可不清才进入注意事项包。
4. 图形优先来自 PPTX/文档真实图形，其次来自带来源与许可的网络真实图形；没有可靠图形时明确留空或标记缺口。
5. 双屏是发布后可选的“授课”能力；实体认证保持独立验收，不阻塞个人组课。
6. 内部 ID 保留在合同和证据中，但不出现在默认 UI。

## 阶段反思

本阶段没有继续堆叠双屏能力。最小正确纠偏是保留底层治理资产，重做个人入口与编排边界；清理必须跟随这个边界，不能先按文件大小删除仍承担真实合同的代码。
